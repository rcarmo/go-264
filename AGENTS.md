# go-264 project rules

The canonical project name is `go-264`. `Makefile` and the vendored `scripts/project-tmp.sh` resolve the root once before child TMPDIR is set: a validated explicit `PROJECT_TMP_BASE/go-264` or absolute `PROJECT_TMP_ROOT` ending in `/go-264` (both must agree); otherwise local writable `/workspace/tmp/go-264` then `/tmp/go-264`, or in CI `${RUNNER_TEMP}/go-264`, the original `${TMPDIR}/go-264`, then `/tmp/go-264`. Invalid explicit overrides fail. Portable CI needs no host `/workspace/Makefile`. The helper snapshots the original TMPDIR before child overrides. Keep rebuildable caches in `cache/<tool>/`, generated binaries/build trees in `build/`, stable test artifacts in `tests/`, retained logs in `logs/`, and isolated disposable scratch in `runs/<purpose>/<run-id>/`; never use ad-hoc top-level paths or home caches. Initialise directories with `make tmp-init` before cache-producing commands.

`Makefile` exports `GOCACHE`, `GOMODCACHE`, `GOPATH`, `XDG_CACHE_HOME`, `PYTHONPYCACHEPREFIX`, `PIP_CACHE_DIR`, `UV_CACHE_DIR`, `TMPDIR`, `TMP`, `TEMP` and `GOTMPDIR` for Go, Python and subprocesses. Direct commands must use the same paths. `scripts/test-profile.sh` creates an isolated test run directory and retains each package's CPU/heap profiles, matching test binary, command, toolchain, revision and log in `/workspace/reports/go-264/tests/<run-id>/`. Use the profiling-aware `make test`, `make test-race` or `make test-purego` targets, including focused tests. After every run inspect cumulative CPU, `alloc_space` and `alloc_objects`; report empty samples or missing profiles, and obtain representative profiles before performance acceptance. `go vet` and architecture-only builds are not test runs.

Retained fixtures live in `/workspace/reports/go-264/fixtures/`; profile evidence in `/workspace/reports/go-264/` (or, without `/workspace/reports`, the resolved root's `tests/` and `logs/` until uploaded to CI artifact storage; `GO264_EVIDENCE_ROOT` can select a durable location). Never include evidence in disposable cache/build/run cleanup. Existing historical fixtures, FFmpeg toolchains and reports in legacy locations are **not** moved or deleted: use `GO264_FIXTURE_ROOT`, `GO264_CONFORMANCE_ROOT`, `GO264_FFMPEG_BIN` or `FFMPEG_SRC` to point at them when needed. FFmpeg source downloads are caches; builds belong under the resolved root's `build/` and build logs under `logs/` or retained per-run evidence. Keep downloaded reference media separate from disposable scratch. Do not replace the missing historical BBB fixture with another encoding.

The Makefile provides no blanket `clean` target. Cleanup is manual, scoped only to this project's resolved root's confirmed disposable `cache/`, `build/` and `runs/` after checking active jobs; it must not remove `tests/`, `logs/`, fixture, report or other-project paths. Validate local and CI fallbacks and both explicit overrides with `scripts/project-tmp.sh`. Test-owned isolated filesystem roots stay under the run directory, with existing symlink and ownership checks intact.

H.264 decoder outputs require exact sample equality against an independent pinned reference. Preserve the supported progressive 8-bit YUV420 scope; do not relax correctness, cancellation or security contracts for speed. For Git, do not rebase.
